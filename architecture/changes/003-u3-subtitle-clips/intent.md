## 문제
openfilm 의 자막은 film 이 아니라 Studio 가 그린다. 원본은 `.vtt` 하나이고 스타일은 film 당 하나다. 그래서 u3 자막이 하는 것을 할 수 없다.
- 자막 한 줄을 클립처럼 옮기거나 자르지 못한다.
- 레이어를 여러 개 두지 못한다.
- 메인·서브 두 줄을 따로 꾸미지 못한다.
- 줄마다 스타일, `*단어*` 강조, 등장 효과를 주지 못한다.

u3 에서 숏폼을 만들던 사람이 openfilm-u3 로 오면 이 기능을 잃는다. 컨셉 문서는 이것을 "추가가 아니라 대체"로 본다(결정 0005).

## 기대 결과
- 자막 한 줄이 타임라인의 웹 페이지 클립 하나다. 다른 클립처럼 옮기고 자르고 지운다.
- 한 줄에 메인과 서브 두 줄이 있다. 줄마다 글, 강조 단어(`*단어*`), 등장 효과, 색·크기를 Studio 에서 고친다.
- 레이어가 여러 개다. 레이어마다 스타일(폰트, 크기, 색, 자막바)이 다르고 트랙이 하나씩이다.
- `.vtt`(받아쓰기 결과 포함)를 가져오면 cue 마다 자막 클립이 생긴다. 같은 입력은 같은 결과를 낸다(결정 0004).
- 코딩 에이전트가 skill 의 자막 지침(대본, 말투, 성격, 전역 지침)을 읽고 자막 클립을 만든다.
- 미리보기 프레임과 내보낸 mp4 프레임이 같다.

범위 밖: 받아쓰기 엔진(whisper asr 변경), 짤·효과음, 자동 생성 파이프라인, 원격 기본 프롬프트(u3 0037).

## 영향 범위
- 사용자: Studio 에서 자막을 편집하는 사람, 자막을 쓰는 코딩 에이전트.
- Studio: 자막 클립 템플릿 페이지, 인스펙터의 props 편집, 기존 자막 패널·오버레이.
- 서버·CLI: `.vtt` 가져오기 명령, skill 목록.
- 기존 기능: Studio 자막 번역, SRT 내보내기, 자막 burn-in. 자막 클립에는 동작하지 않을 수 있다.
- 폰트: u3 의 한국어 폰트(Pretendard, G마켓 산스, 티몬체) 번들.

## 제약
- 결정 0003: 업스트림 코어(`Timeline.tsx`, `captions.mjs` 등)는 등록 수준만 고친다.
- 결정 0004: 가져오기는 결정론이다.
- 결정 0005: 자막은 페이지 클립이고 `.vtt` 는 가져오기 소스로만 쓴다.
- 기존 프로젝트의 Studio 자막을 지우지 않는다.
- 번들 폰트의 재배포 권리는 공개 배포 전에 확인한다(INTENT 제약).

## 열린 질문
- 페이지 클립 인스펙터가 메인·서브·강조·효과 편집을 감당하는가(INTENT 열린 질문).
- 레이어를 무엇으로 표현하는가. 템플릿 복사본인가, 한 템플릿의 prop 인가.
- `.vtt` 가져오기 명령의 형태. `openfilm get subtitles` 로컬 verb 인가, 별도 하위 명령인가.
- u3 skill 을 어떻게 등록하는가. `skills.mjs` 의 네 번째 소스인가.
- 자막 클립이 있는 film 에서 기존 Studio 자막(오버레이, 번역, SRT)은 어떻게 되는가.
- 등장 효과를 페이지의 `frame(t)` 로 그릴 수 있는가(컨셉 문서의 추정).
- 미리보기와 내보내기가 같은 프레임을 내는가(INTENT 열린 질문).
